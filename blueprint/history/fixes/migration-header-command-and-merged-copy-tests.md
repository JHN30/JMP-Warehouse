# Fix: Migration header command and merged copy tests

**Type:** Fix
**Status:** verified
**Branch:** fix/migration-header-command-and-merged-copy-tests
**Fixes:** F-06, F-07

## The problem

- **F-06** ([contract.py](neon_publish/contract.py) `migration_sql`, line 104): every generated
  migration header says "Generated by python neon_publish/main.py --print-migration", but that
  command prints the 30g DDL. Anyone regenerating `30h_game_advanced.sql`,
  `30i_game_play_by_play.sql` or `30j_game_on_court_and_gaps.sql` from the header gets the wrong
  file, and the equality tests fail with no hint why. The SQL itself is correct.
- **F-07** ([test_game_court.py](gold_etl/tests/test_game_court.py)): repeats
  [test_game_pbp.py](gold_etl/tests/test_game_pbp.py) almost line for line (columns equal Silver
  minus provenance, keys, scoped copy, rollback, unknown names) for a different tuple of table
  names, so a change to the copy contract needs the same edit twice.

## The fix

- **F-06.** The header names `--print-migration` for 30g (so `30g_new_tables.sql` stays
  byte-identical) and `--print-migration <feature>` for every other feature. Regenerate the 30h,
  30i and 30j files; only their line 2 changes. No change to the SQL, table lists or CLI.
- **F-07.** One test module, `gold_etl/tests/test_game_copies.py`, replaces both: shared key map
  covering all seven tables of `GAME_PBP_NAMES + GAME_COURT_NAMES`, with the schema, copy-statement,
  rollback and unknown-name checks looped over them. Keep the table-specific assertions (known
  columns per table, zero-row `game_stat_gaps` copy, `COPIED_TABLES` equals sources plus both
  groups, `TABLES`/`SOURCE_NAMES` stay 16). No test is dropped; no production code changes for
  this part. Remove `test_game_pbp.py` and `test_game_court.py`.
- Must not break: the 30g migration file test, `--print-migration` with and without an argument,
  and the four test commands in `AGENTS.md`.
